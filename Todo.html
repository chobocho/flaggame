🚩 청기 백기 게임 (TS + Canvas) 설계 문서

1. 프로젝트 개요

25년 전 오락실/TV에서 유행하던 클래식 '청기 백기' 게임의 웹 버전. 음성 명령(여성 목소리)에 따라 사용자가 키보드로 반응하는 체감형 순발력 게임입니다.

  • 기술 스택: HTML5 Canvas, TypeScript, Web Audio API / Web Speech API (TTS)
  • 렌더링: 100% Canvas API를 활용한 프레임 기반 렌더링 (DOM 요소 최소화)
  • 오디오: window.speechSynthesis를 사용해 한국어 여성 음성(ko-KR)으로 명령 하달

2. 코어 메커니즘 & 조작

동작 단축키 (키보드) 상태 변화
청기 올리기 Q Blue: UP
청기 내리기 A Blue: DOWN
백기 올리기 P White: UP
백기 내리기 L White: DOWN

* 명령이 끝난 후 제한 시간(예: 1.5초) 내에 요구되는 깃발 상태와 현재 상태가 일치해야 성공.

3. 시스템 아키텍처

  • GameEngine: requestAnimationFrame 기반 메인 루프, Delta Time 계산
  • StateManager: 대기 -> 명령 재생 -> 입력 대기 -> 판정 -> (반복/종료)의 FSM 관리
  • CommandGenerator: 난이도에 따른 논리적 명령 생성기 (단일, 연속, 부정형)
  • VoiceManager: Web Speech API 제어, 텍스트 파싱 및 발화 타이밍 동기화
  • Renderer: Canvas 컨텍스트 관리, 캐릭터/깃발/스코어/타이머 드로잉

4. UI/UX 개념도 (Canvas Rendering Target)

* 위 화면은 HTML5 Canvas API의 fillRect, arc, lineTo 등을 사용하여 구현됩니다.

5. 클로드(Claude) 구현 진행 TODO 리스트

클로드에게 아래의 단계를 순차적으로 요청하여 개발을 진행하세요.

  • Phase 1 프로젝트 스캐폴딩 및 게임 루프 구축

    Vite + TypeScript 환경 구성. index.html에 단일 <canvas> 요소 배치. requestAnimationFrame을 활용한 기본 GameLoop 클래스 및 화면 클리어 로직 작성.

  • Phase 2 Canvas 렌더링 시스템 (캐릭터 & 깃발)

    Renderer 클래스 구현. 양손의 상태(UP/DOWN)에 따라 깃발의 위치와 팔의 각도가 변하는 로직 작성. 청기(Left), 백기(Right) 색상 상수화.

  • Phase 3 명령어 생성기 (Command Generator) 논리 구현

    단순 명령("청기 올려")부터 복합 함정 명령("청기 올리지 말고 백기 내려")까지 텍스트를 생성하고, 해당 명령 수행 후 기대되는 최종 목표 상태(Target State)를 계산하는 로직 구현.

  • Phase 4 TTS (Web Speech API) 연동

    VoiceManager를 구현하여 Phase 3에서 생성된 텍스트를 한국어 여성 음성으로 재생. onend 이벤트를 캐치하여 사용자의 입력 대기 타이머(Timer)를 작동시키는 상태 동기화.

  • Phase 5 입력 처리 및 판정 로직

    키보드(Q, A, P, L) 이벤트를 수신하여 깃발 상태 변경. 타이머 종료 시점의 깃발 상태와 Phase 3의 목표 상태를 비교하여 Success/Fail 판정 및 목숨(Life) 차감 로직 구현.

  • Phase 6 난이도 커브 및 폴리싱

    스테이지가 오를수록 제한 시간이 짧아지고, 복합/부정 명령의 등장 확률이 높아지도록 조정. 성공/실패 시 Canvas 파티클 효과나 화면 흔들림(Screen Shake) 효과 추가.

  • Phase 7 도움말(Help) 시스템

    키보드: F1 키로 도움말 오버레이 표시/숨김. 모바일: 화면 우상단에 ❓ 이모지 헬프 아이콘 추가하여 터치로 동일한 도움말 오버레이 호출.

  • Phase 8 모바일 터치 입력 지원

    모바일/태블릿에서 청기/백기 올리기·내리기를 터치로 조작할 수 있도록 화면에 가상 버튼(Q/A/P/L에 대응) 배치. touchstart 이벤트 처리 및 키보드 입력과 동일한 판정 로직 적용.

  • Phase 9 갤럭시 폴드 반응형 렌더링 수정

    갤럭시 폴드7 접힌 화면(커버 디스플레이) 및 펼친 화면(메인 디스플레이) 양쪽에서 Canvas가 올바른 비율로 그려지지 않는 버그 수정. window.resize / orientationchange / visualViewport 이벤트 대응 및 DPR(devicePixelRatio) 재계산 로직 보강.

  • Phase 10 일시 정지 / 이어하기 기능

    일시 정지(Pause) 및 이어하기(Resume) 버튼 추가 (키보드 단축키 + 화면 버튼). 일시 정지 중에는 GameLoop·타이머·TTS를 모두 멈추고, 이어하기 시 정확한 시점부터 재개되도록 상태 보존.

  • Phase 11 TTS↔타이머 사이 입력 공백 제거

    음성 명령 재생 완료 후 타이머 바가 그려지기 전까지 짧은 딜레이 동안 키보드 입력이 무시되는 문제 수정. speechSynthesis.onend 시점부터 입력을 즉시 수신·버퍼링하여, 타이머 시작과 동시에 판정 대상에 포함되도록 처리.

  • Phase 12 시작 화면 단축키 안내

    게임 시작(타이틀) 화면에 조작 단축키 설명 표시: Q(청기 올림) / A(청기 내림) / P(백기 올림) / L(백기 내림), F1(도움말), Space(시작/재시작) 등.

  • Phase 13 게임 오버 재시작 키 변경

    게임 오버 화면에서 Space 키로 재시작 가능하도록 입력 처리 추가. 안내 문구도 "Press SPACE to Restart"로 갱신.

  • Phase 14 캐릭터 일러스트 교체 및 애니메이션

    현재의 도형 기반 캐릭터를 만화풍의 예쁜 2D 여성 캐릭터 이미지(스프라이트)로 교체. 깃발 올림/내림에 따른 팔 동작, 대기 시 호흡(아이들), 성공/실패 시 표정 변화 등 프레임 또는 스프라이트 시트 기반 애니메이션 적용. 단일 파일 빌드 유지를 위해 이미지는 Base64로 인라인 임베드.

  • Phase 15 깃발 이미지화 및 펄럭임 효과

    청기/백기를 단색 사각형이 아닌 이미지(천 질감 포함)로 교체. 바람에 흔들리는 듯한 펄럭임 애니메이션 적용 — 사인파 기반 정점 변형 또는 프레임 스프라이트 사용. 깃발 올림/내림 전환 시에도 자연스러운 흔들림 유지. 단일 파일 빌드 유지를 위해 Base64 인라인 임베드.

  • Phase 16 점수 연동 TTS 속도 가변화

    점수(또는 스테이지)가 올라갈수록 SpeechSynthesisUtterance.rate 값을 점진적으로 증가시켜 명령 발화 속도가 빨라지도록 구현. 최소/최대 rate 범위(예: 1.0 ~ 1.8)와 증가 곡선을 상수화하여 난이도 커브(Phase 6)와 일관되게 조정.
